# Manuscript

The manuscript describing release 4.0 of the pipeline, written from scratch from the 4.0 methods
documentation (`docs/methods/`) and code. It replaces the earlier, pre-4.0 draft, which is kept
outside source control (`/manuscript/`, ignored).

- [manuscript.pdf](manuscript.pdf) and [supplement.pdf](supplement.pdf): the built documents.
- `metadata.yaml`, `sections/*.md`: the main text, in pandoc Markdown, in reading order.
- `supplement/metadata.yaml`, `supplement/S*.md`: the Supplementary Information. Sections S1–S6
  give each stage's finer rules and defaults; `S7_tables.md` is generated (below).
- `references.bib`: the bibliography. Each entry was written by hand; check DOIs and pages against
  the journal before submission.
- `figures/`: the existing pipeline and kernel-ladder SVGs (Figures 1–2), generated by
  `tools/make_figures.py`, plus the results SVG/PDF pairs (Figures 3–12), generated by
  `tools/make_results_figures.py`. Draft captions, definitions and proposed placement are
  in `figures/CAPTIONS.md`. The results plots read only the tracked compact `data/*.csv|json`
  summaries. They never open run directories or invoke the reconstruction pipeline.
- `tools/make_tables.py`: writes Supplementary Tables S1 (kernel ladders, from
  `docs/developer/costs.md`) and S2 (numerical ledger, from `docs/developer/ties.md`) into
  `supplement/S7_tables.md`; do not edit that file by hand.
- `style.css`: page and caption style for the HTML and PDF builds; `tools/svg_to_png.lua` points the
  Word build at PNG renders of the figures.

The stage-by-stage Methods and Supplementary Methods were drafted from `docs/methods/` and checked
against the code of each stage; where a method page and the code disagreed, the text follows the
code.

## Figures

Regenerate Figures 3–12 from the tracked summaries (matplotlib and NumPy required):

```sh
export PYTHONDONTWRITEBYTECODE=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1
export MKL_NUM_THREADS=1 NUMBA_NUM_THREADS=1
export MPLCONFIGDIR="${TMPDIR:-/tmp}/paper42-matplotlib"
nice -n 19 python -P paper42/tools/make_results_figures.py
```

To refresh summaries from completed validation outputs, supply the input locations:

```sh
nice -n 19 python -P paper42/tools/figure_data.py \
  --matrix42 /path/to/matrix42 --matrix41 /path/to/matrix41 \
  --probes /path/to/probes --node-logs /path/to/node-queue/logs \
  --processor 'PREFIX_A=Sapphire Rapids:112' \
  --processor 'PREFIX_B=Ice Lake:76' \
  --mosaic-chromosome chr1 --out paper42/data
```

Replace the path placeholders with the completed inputs, `PREFIX_A` with the
Sapphire Rapids receipt host prefix and `PREFIX_B` with the Ice Lake receipt host
prefix. The repeatable `--processor PREFIX=NAME:CORES` argument is required; the
extractor has no built-in site mapping. The processor names and core counts above,
with the corresponding prefixes, reproduce the current summaries. Prefixes are
used only to interpret receipts and are never written into `data/`.

Use the project's existing analysis Python environment. Extraction reads published
CSV/TSV/JSON tables and streamed VCF records, configs, and completed timing receipts;
it can take several minutes and does not run the pipeline or evaluation. Append `--costs-only`
to refresh the paired-cost table and cost provenance without rescanning VCFs. Source
references stored in the summaries are portable logical paths. `data/provenance.json`
records comparison scope, tolerances, stage coverage and limitations. For an isolated
plot regeneration, pass `--output-dir` to the plotter. Both scripts are deterministic;
plot SVG identifiers and PDF timestamps are fixed. Figures 1–2 and their generator
are unchanged by this results workflow.

## Build

```sh
paper/build.sh
```

Needs pandoc 3 (citations use its built-in citeproc) and, for the PDFs, a Chromium or Chrome
binary on `PATH` or in `CHROME`. The PDF is Chromium's print of the HTML, so no LaTeX is needed.
The build also writes `paper/build/manuscript.{html,docx,tex}` and the same for the supplement;
`paper/build/` is not tracked. The LaTeX output references the SVG figures, which a LaTeX
toolchain must convert (for example with the `svg` package or `rsvg-convert`).

## Placeholders

Text in red boxes, written as `[TO FILL: ...]{.todo}` or in a `::: todo` block, marks content that
cannot be written from the repository alone:

- accuracy on simulated crosses, and the TroMau results, which need the scored outputs of the 4.0
  validation matrix (they live on project storage, not in the repository);
- wall time and memory of whole-genome runs;
- data description details (sample counts, depth, species name, the genetic map used),
  co-authors, affiliations, data accessions and acknowledgements.

Every number that is in the text without a placeholder comes from the repository: the cost and
kernel-ladder tables (`docs/developer/costs.md`), the 4.0 changelog (`CHANGELOG.md`), the numerical
ledger (`docs/developer/ties.md`) and the generated parameter reference
(`docs/reference/parameters.md`).

List the remaining placeholders with:

```sh
grep -n "TO FILL" paper/metadata.yaml paper/sections/*.md paper/supplement/*.md
```
